# 本机 Pi 问卷超时测试

此前 `node poc/ask-stale-overlay.ts` 使用普通主屏 TUI。它测试了 2/3/4 题共 54 个场景，但不能代替本机全屏模式测试。

本机环境检查发现：

- Pi 1.1.0，`tuiMode: fullscreen`。
- 21 个已安装包，启动界面显示 27 个扩展。
- 问卷插件 2.12.0、权限插件 40.1.2（项目测试依赖为 40.0.2）。
- 问卷空闲超时为 60000 毫秒。

## 启动隔离实例

```sh
python3 poc/prepare-local-pi.py --timeout-ms 60000
```

脚本输出独立目录、工作目录和启动命令。在输出的 `cwd` 下运行 `command`。它使用本机已安装包的绝对路径，不安装或更新包。

进入 Pi 后：

1. 输入 `/poc-run 4`（也支持 2、3 题）。
2. 逐题按 Enter，进入确认页。
3. 按 Down，让光标停在 Cancel。
4. 不再按键，等 60 秒。按键会重置空闲计时。
5. 超时后试 `/poc-ping`。日志应出现 `timedOut: true` 的 `questionnaire-result`，随后出现 `ping`。
6. `/poc-exit` 正常结束测试实例。

若由 `interactive_shell` 控制，使用后台实例避免用户键盘接管导致提前提交。观察者应从日志第一行开始读取，避免遗漏已经发生的工具返回事件。

## 证据与边界

输出目录保存 `environment.json`（包版本）、`events.jsonl`（生命周期和测试按键十六进制）、`terminal.log`（终端输出，若宿主支持）。

- 使用实际 CLI、扩展加载、工具执行链和 PTY；模型是固定离线回复，只调用问卷工具。
- 不复制 `auth.json`、真实会话、模型配置或原项目；测试会话和配置写入独立临时目录。
- 关闭安装目录自动补丁，避免改动共享扩展代码。
- 已安装扩展仍然是实际可执行代码，不构成操作系统沙箱。没有复刻原会话的内存状态、项目目标或终端软件。
- 按键日志仅用于测试；不要在测试实例中输入凭据或私人内容。

第一轮全屏测试被接管后在超时前手动提交了 4 个答案；该轮不能算超时验证。

第二轮无人操作的后台全屏实例：四题全部选择完毕、光标停在 Cancel。最后按键时间为 `1791592063429`，工具返回时间为 `1791592123433`，间隔 **60004 毫秒**。结果为 `timedOut: true`、`cancelled: true`、`answerCount: 0`。终端画面显示问卷已经消失，模型继续输出；随后 `/poc-ping` 在 `1791592130767` 正常执行。没有复现残留问卷或 Enter 失效。

同一实例随后测试三题：最后按键时间为 `1791592155453`，超时返回时间为 `1791592215455`，间隔 **60002 毫秒**。同样返回 `timedOut: true`、`cancelled: true`、`answerCount: 0`，模型正常继续，随后 `/poc-ping` 在 `1791592218359` 执行。屏幕显示两轮问卷均已关闭，编辑器可用。
